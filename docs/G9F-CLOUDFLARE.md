# G9f — Cloudflare Access Managed OAuth origin identity (synthetic-only)

**Status: SOURCE-ONLY, LOCAL VERIFICATION, RELEASE NO-GO.** Cloudflare Access Managed OAuth is a candidate for avoiding a custom OAuth authorization-code and consent server. Cloudflare's Access layer can validate its OAuth client authorization and send a signed `Cf-Access-Jwt-Assertion` to a protected origin. Knowledge must independently validate the assertion cryptographically; a raw header is never sufficient.

The module `src/cloudflare-access-auth.mjs` accepts only an operator-pinned `https://<team>.cloudflareaccess.com` issuer, an explicitly configured Access application AUD, approved Access subject identifiers, and up to eight trusted RSA public JWKS. It rejects unexpected signing algorithms, unknown KIDs, invalid signatures, unsafe public keys, issuer/audience/principal mismatch, and expired/future or over-24-hour assertions. An absent `typ` is accepted, as real provider JWS headers need not carry one; other header fields are refused. The output role is ALWAYS read-only even if signed claims assert `knowledge.write`, `admin`, or groups. Cloudflare's Access assertion does not itself establish a separate Knowledge write-consent scope.

The core MCP server now supplies the request object as a second argument to `mcpTokenVerifier(token,req)` so future trusted identity adapters can inspect the signed assertion. Existing functions taking one argument remain compatible. In this increment there is **no new hosted route, CLI entrypoint, Cloudflare configuration, DNS, Access app, token issuer, or actual ChatGPT session**; the adapter is available only to the trusted local server constructor and tests.

**Do not expose `Cf-Access-Jwt-Assertion` to arbitrary Internet callers.** A future ingress must be verified to require Cloudflare Access authorization, strip or overwrite client-supplied identity and forwarding headers, prevent direct origin access, and enforce TLS. Otherwise a client could try to supply an identity header. The verifier's signature validation limits forgeries but does not replace correct ingress or entitlement checks. Exact Cloudflare issuer/AUD/JWKS formats and key rotation must be tested against the real service before claiming compatibility. JWKS must be fetched and refreshed via an independently secured operator mechanism; this source uses pinned keys only.

**Not implemented:** write permission mapping, a secure ChatGPT connected plugin, Cloudflare Access Managed OAuth setup, durable revocation, encrypted live SQLite/FTS/WAL, complete Notion export and migration. Do not use private personal, clinical or business data until separately verified and approved.
